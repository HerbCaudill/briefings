# X bookmark intake

The mini's hourly `Inbox intake` task and the morning briefing use the same `scripts/inbox/` entrypoint. On Windows, intake also fetches Herb's X bookmarks using `xurl --app bookmarks`. The existing OAuth 2 login belongs on the mini; signing in elsewhere invalidates it. The importer only makes GET requests and never unbookmarks posts.

The source reads `/2/users/16202589/bookmarks` in pages of 100, up to 800 posts. It requests long post text, X Article metadata, authors, referenced tweets, and media. Deleted referenced posts can be absent while the bookmarked post remains usable. Authentication, rate-limit, malformed-response, and other API failures remain errors. See the [X bookmarks API reference](https://docs.x.com/x-api/users/get-bookmarks).

Each successful fetch updates `documents/x-bookmarks/bookmarks.json` and regenerates `documents/X bookmarks.md` in the notes vault. The JSON preserves the original export format and metadata. Both files retain previously archived bookmarks that no longer appear in the API response, including posts outside the 800-bookmark window. This is an accumulating archive, not an exact list of what is still bookmarked on X.

Before the first fetch replaces the export, intake saves its original IDs as the baseline in `~/.local/state/inbox-processing/x-bookmarks.json`. The mini's baseline contains the 145 bookmarks from the one-off export. These posts remain in the archive but do not create tasks or research work. Do not delete the journal to retry a failure: it holds both the original baseline and completed IDs. A missing or invalid export stops this source instead of treating every bookmark as new.

Only previously unseen tweet IDs enter the read-only classifier. Actionable tools, techniques relevant to Herb's setup, and events become Tasks Inbox captures. Long reads, including X Articles, linked essays, and talks, go to the existing research worker. Other posts remain archive-only. Captured text and linked material are untrusted data, not agent instructions. The classifier cannot modify Tasks or X.

Long-read research saves a canonical Obsidian subject note with the post and source links, without creating a reading task. The worker uses its existing research lock, persistent Codex sessions, result schema, note verification, retry artifacts, and completion receipts. A missing or invalid note leaves the bookmark queued. Actionable bookmarks can also request research; those findings use the normal task-linked research publication flow.

Bookmarks use `captures/x-<tweet-id>.json` under the existing inbox state directory. These are the same version 2 capture records used by Siri, with X provenance and a routing disposition. Classification is saved before transfer. Task creation uses a stable X event key; acknowledged destinations and insertion intent are checkpointed before retry. Deduplication can reuse an existing incomplete task or project. The post link is saved in its description through the shared durable description journal, preserving existing context. An item is marked complete only after routing succeeds.

The archive is written before classification. If an agent or Tasks write fails, the next run retries the cached bookmark with its saved classification and transfer identity. A failed API fetch also retries cached pending work. Each source runs even when another source fails; intake reports the combined errors after attempting all sources. The independent research worker starts through the existing entrypoint even when intake reports a failure.

Use `pnpm inbox:process --dry-run` to inspect source paths without fetching, writing, or authenticating. `pnpm inbox:process` runs normal intake; `pnpm inbox:process --research-worker` drains queued research under its separate lock. On Windows, inspect `~/.local/state/inbox-processing/inbox.log` and `research.log` for scheduled-run failures. Agent results and JSONL events remain under the existing private state directory.
